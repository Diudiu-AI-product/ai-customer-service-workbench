# 自动化策略说明

## 核心原则

自动化的目标是提升效率，而不是替代判断。

这个项目的定位不是“全自动客服”，而是“在低风险场景下自动处理，在高风险场景下快速回到人工”。

## 支持的意图类型

### 1. 商品与技术问题

常见例子：

- 参数是多少
- 支持什么规格
- 成色怎么样
- 和另一个型号有什么区别

策略目标：

- 基于商品上下文给出简洁、明确的回答
- 尽量避免编造没有依据的信息

### 2. 价格与议价问题

常见例子：

- 能便宜一点吗
- 最低多少
- 别家更便宜
- 多轮压价

策略目标：

- 保持统一议价口径
- 根据议价轮次调整语气或策略
- 避免过度承诺

### 3. 普通客服问题

常见例子：

- 还在吗
- 能发货吗
- 可以拍吗

策略目标：

- 快速回复
- 语气自然
- 尽量缩短用户等待时间

### 4. 无需回复类消息

常见例子：

- 系统噪音
- 非动作型提示
- 不需要明确回应的消息

策略目标：

- 减少无效回复
- 避免打扰用户

## 转人工策略

应该停止自动化、切换人工的情况包括：

- 卖家主动切换到人工模式
- 消息格式异常或像系统消息
- 涉及敏感的站外引导、支付、退款、争议等问题
- 风险较高、语义模糊、需要判断的复杂场景

## 人工接管设计

当前实现采用关键词切换的方式，在产品层面对应的是一个很重要的设计原则：

- 自动化必须允许人工快速接管
- 接管成本必须足够低
- 接管后系统不能继续抢答

虽然现在只是一个简单开关，但这个方向是对的。

## 当前已有的保护措施

- 系统消息识别
- 中括号系统消息过滤
- 敏感关键词过滤
- 人工接管模式
- 消息过期过滤

## 建议补充的保护措施

- 低置信度转人工
- 售后和退款场景的明确规则
- 高风险问题使用固定安全模板
- 人工复核队列

## 需要重点关注的失败类型

- 编造商品事实
- 议价过度
- 回复系统消息
- 人工接管后仍继续自动回复
- 出现敏感站外或支付类话术

## 产品判断逻辑

简单来说：

- 低风险、重复型、信息型问题，优先自动化
- 涉及信任、资金、规则的问题，优先人工
- 系统判断不清楚时，宁可不回或转人工，也不要硬回

这也是这个原型最重要的产品边界之一。
